## 1. 背景介绍

### 1.1 行业背景

随着 AI 技术的发展，传统的"挂号 + 问诊 + 买药"流程正在被重构。用户不再满足于在各个页面之间被动跳转，而是需要一个**懂医疗、能决策、会关怀**的 AI 健康伴侣。

### 1.2 痛点分析

| 痛点       | 现状                               | 本平台解法                                |
| ---------- | ---------------------------------- | ----------------------------------------- |
| 导诊靠猜   | 用户根据症状自己选科室，经常挂错号 | AI 多轮对话理解症状，知识图谱推理推荐科室 |
| 挂号靠抢   | 热门专家放号即秒光，超卖频发       | Redis 原子扣减 + 防刷机制                 |
| 问诊重复   | 每个医生都要从头问一遍病情         | AI 预问诊整理摘要，医生直接看关键信息     |
| 处方看不懂 | 专业术语、用法用量不明确           | AI 通俗解读处方，告知用法禁忌             |
| 买药跑腿   | 拿处方自己找药店比价               | AI 推荐附近药店，一键下单配送             |
| 看完即结束 | 没有后续关怀                       | AI 主动回访 + 用药提醒 + 健康管理         |

### 1.3 项目目标

构建一个 **B+C 深度联动**的新一代医疗平台：

- **C 端**：以 AI Agent 为"第一联系人"的支付宝小程序，智能处理导诊、挂号、问诊、购药、健康管理
- **B 端**：为医生和管理员提供 Web 管理后台，基于预设的大型三甲医院，支撑科室、医生、排班、接诊、处方、药品等业务管理，同时为 AI Agent 提供数据能力

### 1.4 核心挑战

> **如何让 AI Agent 不仅是一个"问答机器人"，而是能真正完成业务闭环的智能助手？**

答案：Agent 能调用真实 API 完成挂号、下单、开方等操作，不只是生成文本。

## 2. 产品概述

### 2.1 产品定位

以 AI Agent 为核心的新一代医疗服务平台。"懂医疗"——知识图谱驱动精准导诊；"能决策"——综合病情和号源推荐最优方案；"会关怀"——情感识别 + 主动回访 + 用药提醒。

### 2.2 用户角色

| 角色       | 标识    | 描述                                     | 使用端               |
| ---------- | ------- | ---------------------------------------- | -------------------- |
| 患者       | PATIENT | 使用 AI Agent 进行导诊、挂号、问诊、购药 | C 端（支付宝小程序） |
| 医生       | DOCTOR  | 管理排班、接诊、开具处方、查看病历       | B 端（Web 后台）     |
| 医院管理员 | ADMIN   | 维护科室、医生信息，管理排班和号源池     | B 端（Web 后台）     |

### 2.3 核心闭环

```
用户描述症状 → AI 智能导诊 → 科室/医生推荐 → 预约挂号 → 挂号成功
    → AI 预问诊整理 → 医生接诊 → 开具处方 → AI 解读处方
    → 推荐药店 → 一键购药 → 用药提醒 → 主动回访
```

### 2.4 技术栈

| 层级     | 技术选型                                                      |
| -------- | ------------------------------------------------------------- |
| C 端     | 支付宝小程序 + TypeScript + Ant Design Mini + AntV F2         |
| B 端     | Umi + React + TypeScript + Ant Design + AntV + Zustand + Less |
| 后端     | Spring Boot + MyBatis-Plus + PostgreSQL + Redis               |
| AI Agent | Python + LangGraph + LangChain                                |
| 知识图谱 | Neo4j                                                         |
| 向量检索 | PostgreSQL pgvector 扩展（备用 RAG）                          |

```
│  C 端：支付宝小程序       │    │  B 端：Web 管理后台            │

│  │ 🤖 AI Agent 对话页   │ │    │  │科室/医生│ │医生工作台  │  │
│  │ 挂号/问诊/购药/档案   │ │    │  │科室/排班 │ │接诊/开方  │  │
│  └─────────────────────┘ │    │  └─────────┘ └───────────┘  │
└──────────┬───────────────┘    └──────────────┬──────────────┘
           │            HTTPS (Bearer Token)     │
           └──────────────┬─────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────────┐
│  Spring Boot（BFF + 业务服务 + Agent 网关）                        │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐           │
│  │ 用户鉴权  │ │ 业务API  │ │ Agent网关 │ │ 号源并发  │           │
│  └──────────┘ └──────────┘ └─────┬────┘ └────┬─────┘           │
└──────────────────────────────────┼────────────┼─────────────────┘
          ┌─────────────────────────┘            │
          │ HTTP 工具调用                          │ 读写 / 缓存
          ▼                                       ▼
┌──────────────────────────────┐   ┌─────────────────────────────┐
│  Python Agent（LangGraph）    │   │  数据层（全部由 Java 访问）    │
│  ┌──────────┐ ┌────────────┐ │   │  ┌────────────┐ ┌────────┐  │
│  │ LangGraph│ │ 情感识别    │ │   │  │ PostgreSQL │ │ Redis  │  │
│  │ 对话编排  │ │ 话术调整    │ │   │  │ +pgvector  │ │缓存/锁 │  │
│  │ 工具调用  │ │            │ │   │  │ 业务数据    │ │号源·会话│  │
│  └──────────┘ └────────────┘ │   │  │ 排班·处方   │ │防刷    │  │
│  ⚠️ 不直接访问任何数据库      │   │  │ 订单·用户   │ └────────┘  │
│  所有数据访问经 Java API      │   │  └────────────┘             │
│                              │   │  ┌───────────────────────┐  │
└──────────────────────────────┘   │  │ Neo4j（知识图谱）       │  │
                                   │  │ 症状->疾病->科室->药品  │  │
                                   │  │ ->禁忌                 │  │
                                   │  └───────────────────────┘  │
                                   └─────────────────────────────┘
```

**核心原则**：Python 负责"思考和规划"，Java 负责"权限、数据和执行"。Python Agent 不直接访问任何数据库，所有数据访问（含知识图谱）统一经 Java API 完成。C 端和 B 端共用同一个 Spring Boot 后端，按 API 路径和角色鉴权区分。

## 5. C 端模块详情（支付宝小程序）

### 5.1 登录与患者档案

#### 5.1.1 登录方式

本系统为课程演示项目，C 端采用**预设演示账号**方案，无需支付宝授权流程。

```
打开小程序 → 自动以预设患者身份登录 →
  ├── 首次使用 -> 填写档案（姓名、性别、出生日期、过敏史）-> 进入对话页
  └── 非首次 → 直接进入对话页
```

**业务规则**：

- 系统预置一个演示患者账号（姓名、手机号已预设）
- 过敏史为选填项，但建议用户如实填写，以便药物禁忌检测时使用
- 首次填写后，过敏史可在健康档案中修改
- 如需切换患者身份，在健康档案中手动修改即可

#### 5.1.2 患者档案页面

**展示内容**：姓名、手机号（脱敏显示）、性别、出生日期、年龄（由出生日期实时计算）、过敏史。

**操作**：编辑个人信息、修改过敏史。

### 5.2 AI Agent 对话页（核心页面）

#### 5.2.1 页面结构

```
┌─────────────────────────────────┐
│  🏥 智能医疗助手          [···] │  顶部
├─────────────────────────────────┤
│                                 │
│  🤖：您好，我是您的健康助手       │
│      请问有什么可以帮您？         │
│                                 │
│  👤：我头疼三天了，还有点发烧      │
│                                 │
│  🤖：听起来您很不舒服，别担心...   │
│      我先帮您梳理一下：           │
│      1. 体温大概多少度？          │
│      2. 头疼是哪个部位？          │
│      3. 有没有药物过敏史？        │
│                                 │
│  ┌─────────────────────────┐    │
│  │ 🏥 挂号确认              │    │
│  │ 张医生 | 神经内科         │    │
│  │ 明天 09:00-09:30        │    │
│  │ [确认挂号]  [取消]       │    │
│  └─────────────────────────┘    │
│                                 │
├─────────────────────────────────┤
│  💬 输入消息...          [发送] │
└─────────────────────────────────┘
```

**交互说明**：

- 对话采用气泡式布局，流式输出（逐字显示）
- 确认卡片（挂号/购药）嵌入在对话流中，可点击操作
- 支持展示工具调用轨迹（"正在查询知识图谱..."→"正在查询排班..."）
- 输入框支持文字输入

#### 5.2.2 智能导诊

**流程**：

```
阶段1：症状采集
  AI 追问症状细节——部位、持续时间、严重程度、伴随症状、体温等

阶段2：风险评估
  紧急情况（胸痛/大出血/呼吸困难）→ 建议立即就医，不推荐挂号
  非紧急 → 继续导诊

阶段3：科室推荐
  查询知识图谱 → 返回推荐科室 + 理由（如"头痛伴发热常见于神经内科相关疾病"）

阶段4：医生推荐
  查询排班 → 推荐 3 位医生，附理由
  排序：好评率 + 号源余量 + 出诊时间
  展示：医生姓名、职称、擅长、好评率、可约时间

阶段5：挂号引导
  "要帮您挂号吗？" → 用户确认 → 进入挂号流程
```

**业务规则**：

- 紧急症状必须优先提示就医，这是医疗安全底线
- 科室推荐必须有可解释理由（来自知识图谱），不可只给结论
- 所有 AI 建议标注"AI 建议仅供参考，不能替代医生诊断"

## 7. AI Agent 功能设计

### 7.1 Agent 定位

> **Agent 不是 Chatbot。** Chatbot 只能生成文本，Agent 能调用真实 API 完成业务操作。

判断标准是四个环节的闭环：**感知环境 → 自主决策 → 执行操作 → 观察结果**。

### 7.2 核心能力

| 能力       | 描述                                         | 优先级 |
| ---------- | -------------------------------------------- | ------ |
| 意图识别   | 判断用户是想导诊、挂号、问诊、购药还是闲聊   | P0     |
| 多轮对话   | 追问症状细节，收齐必要参数再行动             | P0     |
| 工具调用   | 调用知识图谱、排班查询、挂号草稿、购药下单等 | P0     |
| 可解释推荐 | 推荐科室/医生时说明理由                      | P0     |
| 处方解读   | 通俗语言解释处方内容                         | P0     |
| 情感识别   | 识别焦虑/疼痛，调整话术                      | P1     |
| 主动关怀   | 问诊后回访、用药提醒                         | P2     |

### 7.3 对话流程

```
用户输入 → 意图识别
    ├── 症状导诊 → 追问细节 → 知识图谱 → 科室推荐 → 医生推荐 → 挂号
    ├── 挂号意图 → 查排班 → 推荐医生 → 挂号
    ├── 问诊意图 → 预问诊 → 整理摘要 → 推送医生
    ├── 购药意图 → 查处方 → 查药店 → 下单
    └── 其他 → 通用对话 + 情感安抚
```

### 7.4 工具体系

Agent 通过调用工具来完成业务操作。工具分为两类：

| 类型         | 执行位置                       | 示例                         |
| ------------ | ------------------------------ | ---------------------------- |
| 知识图谱查询 | Python -> Spring Boot -> Neo4j | 症状->科室推荐、药物禁忌检测 |
| 业务工具     | Python -> Spring Boot          | 排班查询、挂号草稿、购药下单 |

**核心工具**（MVP）：

| 工具         | 类型 | 描述                        |
| ------------ | ---- | --------------------------- |
| 知识图谱查询 | 图谱 | 症状→科室→医生→药品→禁忌    |
| 排班查询     | 业务 | 按科室/日期查医生排班和号源 |
| 医生查询     | 业务 | 按科室/医院筛选医生         |
| 患者档案查询 | 业务 | 获取过敏史等                |
| 挂号草稿     | 业务 | 生成挂号草稿（不扣号源）    |
| 预问诊提交   | 业务 | 提交病情摘要                |
| 处方查询     | 业务 | 查询处方详情                |
| 药店查询     | 业务 | 查附近药店（Mock）          |
| 购药草稿     | 业务 | 生成购药订单草稿            |
| 用药提醒设置 | 业务 | 设置用药提醒计划            |

### 7.5 写操作安全机制

所有写操作（挂号、购药）遵循**两段式协议**：

```
阶段A：草稿生成
  Agent 收集参数 → Java 校验 → 生成草稿（不写库）
  → 返回确认卡片给用户

阶段B：用户确认
  用户点击确认 → Java 重新鉴权 → 执行真实操作
  → 返回业务凭证
```

**安全要点**：

- Python Agent 不直接操作数据库
- 身份信息由 Java 从 Session 注入，不信任 Agent 传来的任何身份字段
- 草稿有时效性（30 分钟），过期作废
- 同一草稿不可重复消费

## 8. 创新点设计

### 8.1 情感化交互（创新方向 A）

**设计理念**：Agent 不只是冷冰冰地处理业务，能感知用户情绪并做出恰当回应。

| 场景 | 识别信号                       | Agent 响应                     |
| ---- | ------------------------------ | ------------------------------ |
| 焦虑 | "是不是得了重病""会不会很严重" | 安抚 + 理性分析 + 引导就医     |
| 疼痛 | 描述剧烈疼痛                   | 优先处理 + 紧急建议 + 快速导诊 |
| 困惑 | "这个药怎么吃""看不懂"         | 通俗解读 + 分步说明            |
| 满意 | 感谢                           | 温馨回应 + 引导后续            |

**主动关怀节点**：

| 触发时机     | 关怀内容                         |
| ------------ | -------------------------------- |
| 挂号成功     | 就诊前一天推送提醒               |
| 问诊后 3 天  | "您好些了吗？药按时吃了吗？"     |
| 购药后       | 按处方频次推送用药提醒           |
| 处方即将用完 | "药品快吃完了，需要复诊续方吗？" |

### 8.2 知识图谱推理（创新方向 B）

**四个核心查询场景**：

**场景一：症状导诊**

```
用户："头痛 + 发热"
图谱查询：哪些疾病同时有这两个症状？→ 归属哪些科室？
结果：推荐神经内科（偏头痛）、呼吸内科（上呼吸道感染）
      → 根据追问细节进一步缩小范围
```

**场景二：可解释推荐**

```
用户："为什么推荐张医生？"
图谱查询：张医生擅长哪些疾病？→ 与用户症状是否匹配？
结果："张医生擅长偏头痛治疗，与您的症状匹配，且好评率 98%"
```

**场景三：药物禁忌**

```
医生开具处方：布洛芬 + 阿司匹林
图谱查询：两种药物之间是否存在 INTERACTS_WITH 关系？
结果：检测到相互作用风险 → 阻断保存 → 提示医生
```

**场景四：过敏风险**

```
处方药品：阿莫西林
患者过敏史：青霉素
图谱查询：阿莫西林是否含青霉素成分？
结果：检测到过敏风险 → 高亮警告 → 阻断购药
```

### 8.3 号源防超卖（创新方向 C）

**方案**：Redis Lua 脚本原子扣减。

```
流程：
1. 用户点击"确认挂号"
2. Java 执行 Lua 脚本（原子操作）：
   - 检查 schedule:{id}:remaining_slots > 0
   - 是 → 扣减 1，返回成功
   - 否 → 返回"号源已抢完"
3. 成功 → 写入 PostgreSQL 挂号记录
4. 失败 → 提示用户重新选择

防刷号：同一用户对同一排班 5 秒内仅允许一次请求
```

## 9. 非功能需求

### 9.1 性能

| 指标               | 目标    |
| ------------------ | ------- |
| Agent 对话首字响应 | < 2 秒  |
| 挂号接口响应       | < 500ms |
| 号源查询 QPS       | ≥ 1000  |
| 列表页加载         | < 1 秒  |

### 9.2 安全

| 要求       | 实现方式                                         |
| ---------- | ------------------------------------------------ |
| 身份认证   | 演示账号登录（C 端）+ 账号密码登录（B 端）       |
| 敏感数据   | 手机号 C 端脱敏展示，B 端（医生/管理员）明文展示 |
| 防超卖     | Redis Lua 原子扣减                               |
| 防刷号     | 同用户同排班 5 秒频率限制                        |
| 写操作安全 | 草稿→确认两段式，SHA-256 参数校验                |
| AI 免责    | 所有 AI 输出标注"AI 建议仅供参考"                |

### 9.3 合规

| 要求         | 说明                                                       |
| ------------ | ---------------------------------------------------------- |
| AI 免责声明  | 所有 AI 生成内容标注"AI 建议仅供参考，不能替代医生诊断"    |
| 紧急情况处理 | 识别胸痛、大出血、呼吸困难等紧急症状，优先建议就医而非挂号 |
| 数据最小化   | 仅收集医疗服务必需的个人信息                               |

### 9.4 兼容性

| 端           | 要求                 |
| ------------ | -------------------- |
| 支付宝小程序 | 基础库版本 ≥ 2.0     |
| B 端 Web     | Chrome 90+、Edge 90+ |
